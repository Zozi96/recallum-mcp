# QA plan — S005: SessionStart↔benchmark parity, dry-run, observed-run (or documented gap)

## Risks and cheapest detection layer

1. **Critical — dry-run fabricates success or traces.** The benchmark CLI currently errors when no command follows `--`, and `run_once` can only emit `complete`/`incomplete`. If S005's no-agent path instead emits empty `complete` runs, nonzero rates, or probe events, the "no fabricated success, no agent traces" criterion fails. Unit: build a dry-run payload as the harness would and assert every run is `omitted` (as `status: "skipped"` or a documented equivalent), has zero `events`, and the rendered report shows `coverage 0.0`, no nonzero rates, no `misses` from empty data. Unit is cheapest because this is pure payload/report logic with no client process.
2. **High — dry-run payload fails validation.** `validate_runs` allows only `complete|incomplete|skipped` and rejects unknown fields. A literal `"omitted"` status or a dry-run marker field would make the committed runs file invalid, regressing the S004 evaluator. Unit: the dry-run payload round-trips through `validate_runs(load_scenarios(SCENARIOS))` and `eval_agent_workflow.py` renders without error.
3. **High — parity note drifts from the texts it claims to verify.** The note (in the S004 runbook/matrix doc) must name, per client, the same context/recall/capture tool names the benchmark assumes to discover and the same fail-open behavior. The benchmark probe exposes only `context`+`recall` (`ALLOWED_TOOLS`); SKILL.md and `recallum_hook.py` carry per-client prefixes and fail-open text. If the note claims a mismatch that no diff fixes, or claims parity with no checkable basis, AC 1 is decoratively "done". Unit (static doc↔code consistency): parse the parity note and assert (a) for every client in the S004 matrix the note lists `context`/`recall` and the capture tools, (b) the note's per-client prefixes equal the SKILL.md table and hook `_tool()` prefixes (`mcp__recallum__`, `mcp__plugin_recallum-memory_recallum__`, `recallum__`, Cursor "Available Tools"), (c) fail-open is stated, and (d) the note's mismatch claim is consistent with an actual diff in the tree or says "no mismatch found" when none exists.
4. **High — observed-run report claims evidence it does not have.** AC 4 demands exactly one outcome, stated explicitly: observed runs, or a gap record when no client is installed. If the report mixes fixture data into observed cells, or claims an observed run for a client absent from the host, the honesty criterion fails. Integration: on the execute host, probe which client CLIs exist (cursor/codex/claude/grok); assert the S005 report states the outcome the host actually supports, every claimed observed cell has `source: "observed"` runs with `run_id`/`client_version` in `scripts/agent_workflow_runs.json`, and every other matrix cell is marked an explicit gap.
5. **Medium — versioning list vs enforced validator drifts.** Runbook forbids `prompt, content, reasoning, credentials, credential`; `validate_runs` enforces exactly `_FORBIDDEN_FIELDS`. Unit: assert committed `agent_workflow_runs.json` passes `load_runs`, contains no forbidden fields, no `query` in events, and the runbook's forbidden set equals the code constant.
6. **Medium — parity review regresses existing guidance.** Adjusting SKILL.md/hook for a "mismatch" could break `plugins/recallum-memory/tests/test_plugin.py` or the workflow benchmark unit tests. Unit: the full fast lane including `test_agent_workflow_benchmark.py` and `test_plugin.py` stays green; the three existing scenarios still run complete via `fake_workflow_agent.py`.

## Checks, fixtures, and layers

- **Unit — dry-run honesty (new behavior):** payload as in risk 1; all runs marked omitted with zero events; report `coverage_rate == 0.0`, no nonzero critical/applied rates, no fixture-`source` values. Deterministic, offline.
- **Unit — dry-run round-trip:** payload passes `validate_runs` with the committed `agent_workflow_scenarios.json`; `eval_agent_workflow.py` renders it without error.
- **Unit — parity consistency:** static parse of the parity note against `ALLOWED_TOOLS`/probe tool set, SKILL.md tool table, hook `_tool()` prefixes, and fail-open statements (SKILL.md unavailability text, hook `VISIBILITY_HINT`/digest fail-open). Mismatch claim ⇔ diff present, or "no mismatch found" with no diff.
- **Unit — runs-file integrity:** committed `scripts/agent_workflow_runs.json` loads under `validate_runs`; forbidden fields and `query` absent; observed runs carry `run_id`, `client_version`, `client`.
- **Integration — dry run of the harness:** the no-agent invocation (new flag or runbook-documented procedure) exits 0, emits a versioned payload S005 labels as the dry run, and the rendered report shows the omitted marks. Integration, not unit, because it proves CLI wiring into the report path.
- **Integration — observed-run or gap outcome (host-dependent):** stage 8 inventory of host client CLIs; the S005 report's stated outcome must match the host. Observed cells must trace to `source: "observed"` runs; uncovered cells must be explicit gaps. If no client is installed, the dry run plus the gap record is the pass evidence.

## Operational done criteria

Stage 8 returns pass only when: the fast lane (`uv run pytest tests/unit` plus the plugin suite) is green, including dry-run honesty, dry-run round-trip, parity-consistency, and runs-file integrity tests; the parity note exists in the S004 runbook/matrix doc, lists per-client context/recall/capture tool names matching SKILL.md and the hook, states fail-open, and is either backed by a real diff or says "no mismatch found"; a harness dry run executes and its rendered report shows omitted marks, zero agent traces, and zero success values; and the S005 report states exactly one outcome that matches the host client inventory, with every observed cell backed by valid `observed` runs and every uncovered cell an explicit gap. Any skipped, retried, or environment-blocked check is fail/block, not pass. No credentials, no provisioning, and no installed client are required for pass — "no client installed + clean dry run" is pass by the story's completion rule.

## Blocking dependencies

S004's runbook and matrix must have landed at the paths the consistency test reads — without them there is no parity-note home or matrix to check against (blocked, per contract). Locked `uv` toolchain; committed `scripts/agent_workflow_scenarios.json`, `fake_workflow_agent.py`, `eval_agent_workflow.py`; loopback MCP probe only. The host's client inventory determines which outcome is verifiable; no client, credentials, network, or MCP server beyond the probe is required.

## Deliberate coverage gaps

- No real observed agent sessions for Cursor/Codex/Claude/Grok are executed at stage 8, and none is provisioned: host-dependent and explicitly optional by the story. When clients are absent, the gap record is trusted for the "unavailable" claim (checked against the host binary inventory) but real behavior parity across clients is never proven.
- No CI gate on observed runs (out of scope by story).
- No verification that the parity note is *behaviorally* true in live sessions — only that the committed texts agree with each other and the benchmark's assumed tool set.
- No re-audit of S004's matrix repetition counts or scenario-fixture semantics beyond `validate_runs` round-trips; no ranking, telemetry, `recall_usage_weight`, or persistence checks (out of scope).
